Servidores de Report Manager

Tres formas de servir informes. Se diferencian en quién diseña los informes y en cómo se integran.

Los tres ejecutan los mismos ficheros .rep, diseñados con cualquier diseñador de Report Manager. Empiece por lo que necesite hacer con ellos — y puede usar más de uno.

ServidorQué haceElíjalo si…
Servidor de informes web
(repwebexe)		 Ejecuta un informe con sus parámetros y devuelve el PDF, por web. ya diseña sus informes y sólo necesita ejecutarlos desde su web o su sistema. Como CGI, como servicio con API o en Docker. Windows y Linux, más de 20 años en producción.
Reportman Server Almacén de informes, diseñador web con copiloto de IA y API pública. quiere que su equipo diseñe en el navegador, con usuarios, grupos y permisos, y ejecutar los informes por API. Un solo contenedor Docker.
TCP Report Server Procesa informes para clientes de escritorio con su propio protocolo TCP. sus clientes son aplicaciones de escritorio y quiere que el servidor haga el trabajo: multiproceso, sin web por medio.

Los dos servidores web, uno al lado del otro

Se confunden a menudo porque los dos son «un servidor de informes» y los dos pueden correr en Docker. La diferencia no es la edad: es si los informes se diseñan ahí.

  • El servidor de informes web (repwebexe) es el veterano: un binario nativo para Windows y Linux, desplegado clásicamente como CGI tras Apache o IIS, y ahora también servicio con API y con imagen Docker publicada. No diseña: usted sube los .rep que diseñó en otro sitio. Detalles.
  • Reportman Server es el nuevo: un contenedor con el motor, el almacén de informes y un diseñador en el navegador con copiloto de IA, más su API. Es donde los informes nacen y cambian. Detalles.

Puede usar los dos, y muchas instalaciones lo harán. Si viene de repwebexe, no tiene que cambiar nada: sigue sirviendo exactamente lo que sirve hoy. Añada Reportman Server para que su equipo diseñe en el navegador, y los .rep que salgan de ahí son los mismos que repwebexe ya ejecuta — también los leen el servidor TCP, el diseñador Delphi y su propia aplicación.

Desde ahí puede llevar su aplicación a la API a su ritmo, informe a informe. No hay fecha de corte ni día en que lo de antes deje de funcionar: un despliegue CGI de veinte años y un contenedor con el diseñador web son dos puertas a los mismos informes.
