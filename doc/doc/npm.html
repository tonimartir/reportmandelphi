Report Manager in JavaScript: the npm packages

Esta página en español

The @reportman/* packages on npm are the Report Manager engine written in JavaScript: they open a .rep report, lay it out and write its PDF with no native binaries, no WebAssembly, no Docker and no operating-system dependencies. They run in Node.js and in the browser, and they are a translation of the .NET engine of the same release: the two are meant to give the same output for the same report.

Preview. This is the 4.1.0 preview, published under the npm tag next (npm install @reportman/node@next). The API may still change before the final 4.1.0, so pin the exact version you install if you build on it now.

Requirements

Node 22.12 or later. The packages are ES modules and there is no CommonJS build; a CommonJS program loads them with require(), which Node supports for ES modules. In the browser they need no bundler plugin: they are plain JavaScript.

The two steps: describe the parameters, then run

A report is run in two steps, as in the other engines. First you ask it what parameters it has, so your program (or your user) can fill them in; then you run it with their values. The host gives the engine the report bytes, the data access and the fonts — the engine itself does no I/O.

import { writeFileSync } from 'node:fs';
import { openReport, sqlite } from '@reportman/node';

const report = await openReport('invoices.rep', {
  connections: { SAMPLES: sqlite('samples.db') },
  fonts: {}, // the TrueType fonts of the system; without it, the 14 standard PDF fonts
});

// Step 1: what the report asks for
console.log(await report.describeParameters());

// Step 2: run it with their values
writeFileSync('invoices.pdf', await report.executeToPdf({ FIRST_ORDER: 7, LAST_ORDER: 9 }));

From the command line, and without writing code

@reportman/node installs reportman-pdf, which does the same two steps from a shell:

npm install @reportman/node@next
npx reportman-pdf invoices.rep --describe --sqlite SAMPLES=samples.db
npx reportman-pdf invoices.rep -o invoices.pdf --sqlite SAMPLES=samples.db -paramFIRST_ORDER=7 -paramLAST_ORDER=9

And to see the sample reports running without installing anything or writing a line of code, @reportman/server serves them with its own console and API explorer:

npx @reportman/server --samples

It writes the samples and their database into ./reportman-data, prints the console key and listens on http://127.0.0.1:8080/. The explorer runs each sample to PDF, metafile, text or CSV, and shows the same call for curl, PowerShell, JavaScript, C# and Delphi.

That server speaks the same API as Reportman Server and reads the same data folder, but it does not design reports: see the four Report Manager servers side by side.

The web designer, inside your own application

The report designer also runs in the browser, and a Node.js application can serve it itself. The designer is a custom element, <reportman-designer> (@reportman/designer), and its server side is @reportman/designer-server, mounted on a route of your own application — node:http, Express or Fastify. It is served from your own origin, so it shares your session, and it needs no container and no .NET:

import express from 'express';
import { createDesignerServer, nodeHandler } from '@reportman/designer-server';

const designer = createDesignerServer({
  dataPath: './reportman-data',          // the reports and the connections
  authorize: (check, request) => request.raw.user?.canDesignReports === true,
});

const app = express();
app.use(nodeHandler(designer));          // /api/designer/* and the designer at /designer/
app.listen(3000);

It opens the reports of a data folder laid out as the one of Reportman Server, saves them as the same plain .rep XML the Delphi and .NET designers read, previews their PDF with the JavaScript engine, and reads the schema of your connections for the SQL editor. Who may design is your application’s business: without authorize the designer answers only the machine it runs on, and the check it is given says what is being asked — open or run the reports of an alias, save in it, or open data and evaluate expressions.

The AI copilot is not part of it: the assistant lives in Reportman Server, and the designer opens without it here (no-ai).

@reportman/designer and @reportman/designer-server arrive on npm with the next publish of the preview. Their sources are already in the repository, and the designer live demo runs them in your own browser: there the whole designer —its server side too— works inside the page, with no server at all, and that page relays its copilot to the Report Manager AI service.

Databases

The engine reads its data through a driver package, one per backend, with the same behaviour as the .NET providers. Install the one you need next to @reportman/node:

DatabasePackage
PostgreSQL@reportman/driver-postgres
MySQL and MariaDB@reportman/driver-mysql
Microsoft SQL Server@reportman/driver-mssql
Firebird@reportman/driver-firebird
Reportman DB Agent, through the Hub@reportman/driver-http

SQLite needs no driver: @reportman/node reads it with Node's own node:sqlite. The Agent driver is the only one that also works in the browser, because it talks HTTP to the Reportman DB Agent through the Hub instead of opening a database connection itself.

Reports saved as XML, and reports saved as DFM

As in the .NET engine, the readers take XML .rep files, plain or compressed, and those need nothing extra. A report that Delphi saved in a DFM form needs the optional @reportman/dfm package, which converts it to the XML Delphi writes for it; @reportman/node uses it on its own when it is installed. The other way out is to save the report again as XML, from the designer or with reptotxt -xml.

Try it, and the reference

  • The live demo — the sample reports run in your own browser, with these same packages: the form of the parameters, the preview of the pages and the PDF.
  • The designer live demo — the web designer itself in your browser: open a sample report, change its items, expressions and SQL, preview its PDF and save it.
  • The examples gallery — the eleven sample reports with a picture of their first page, their .rep files, the PDFs the engine makes of them and how to run each one.
  • @reportman/node on npm — and from there every other package of the set.
  • The engine in TypeScript — what each package does, the rules it is built under and how it is tested against the .NET and Delphi engines. Each package has its own README with its API.

The report files are the same ones the Delphi and .NET designers open, so a report designed with either of them runs here unchanged. See also the .NET library and the command line tools.
