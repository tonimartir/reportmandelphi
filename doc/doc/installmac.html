Report Manager on macOS (Lazarus, Cocoa)

The Lazarus packages of Report Manager (engine with PDF export, LCL preview and printing, and the embeddable designer), their examples and the Report Manager Designer build on macOS with Lazarus and the native Cocoa widgetset. They use the same .rep report files as Windows and Linux.

Tested on macOS 11 Big Sur (Intel, x86_64) with Lazarus 4.8 and Free Pascal 3.2.2: the designer test suite, the preview against the PDF output, the examples and the database drivers against real PostgreSQL, MySQL, Firebird and SQLite servers. There is no ready-made macOS application to download yet: build it from the source code as shown below.

Requirements

  • The Xcode Command Line Tools: xcode-select --install (Free Pascal needs the Apple linker).
  • Lazarus with Free Pascal 3.2.2 (tested with Lazarus 4.8), or the toolchain the script build/macos/setup-toolchain.sh installs, see below.
  • At run time, to measure and shape the text: FreeType, fontconfig and HarfBuzz. With Homebrew: 
    brew install fontconfig harfbuzz
    or without Homebrew, build/macos/build-deps.sh builds them from their sources in your user folder (no sudo) and links them in ~/lib. ICU is the one of macOS.
  • For HTTPS (the AI assistants and the Reportman DB Agent driver): OpenSSL 3, brew install openssl@3. The OpenSSL 0.9.8 that macOS keeps for compatibility is never used: it cannot verify certificates. An application can ship libssl.3.dylib and libcrypto.3.dylib in Contents/Frameworks of its bundle instead.

Applications started from the Finder do not receive DYLD_LIBRARY_PATH. The engine looks for each library in Contents/Frameworks of the application, next to the executable, in ~/lib, /usr/local/lib and the Homebrew and MacPorts folders.

The Lazarus packages

Install them as on the other platforms, from the source code (GitHub, SourceForge) or from the Online Package Manager (the changes for macOS are in the source code and reach the Online Package Manager with its next update). From a terminal, in the folder of the source code:

LAZBUILD=lazbuild sh packages/fpc/build_fpc.sh

Examples

The three examples of examples/lazarus (see Lazarus examples) build and run on macOS:

lazbuild examples/lazarus/pdfconsole/pdfconsole.lpi
lazbuild examples/lazarus/preview/preview.lpi
lazbuild examples/lazarus/designer/designer.lpi
examples/lazarus/pdfconsole/pdfconsole      # writes sales.pdf
open examples/lazarus/preview/preview.app
open examples/lazarus/designer/designer.app

Lazarus writes the LCL examples as application bundles (preview.app, designer.app) next to their projects: open them from the Finder or with open.

Build the Report Manager Designer

Two scripts of the source code prepare everything in your user folder (~/dev), without sudo and without touching /usr/local:

build/macos/setup-toolchain.sh     # Free Pascal 3.2.2, Lazarus 4.8 and ZeosDBO in ~/dev
build/macos/build-deps.sh          # FreeType, HarfBuzz and fontconfig
. ~/dev/env.sh                     # lazbuild and fpc in the PATH
LAZBUILD=lazbuild sh packages/fpc/build_fpc.sh
lazbuild --no-write-project repman/lcl_designer/repmandesigner_lcl.lpi
open repman/repmandesigner_lcl.app

setup-toolchain.sh uses the official Free Pascal disk image without installing it and the official Lazarus 4.8 archive. It also applies two corrections to the Cocoa widgetset of Lazarus (build/macos/patches):

  • An application could stop when a window with scroll bars is closed right after its layout changes. That happens with the classic scroll bars of a mouse; a trackpad uses overlay scroll bars.
  • Every row of a list box lost a little memory.

Apply them to your own Lazarus as well: patch -d <lazarus folder> -p1 < build/macos/patches/<file>.patch, then rebuild the IDE or your project.

Databases

Both direct database drivers of the engine work on macOS:

  • FireDAC connections, opened with SQLdb: PostgreSQL, MySQL or MariaDB, Firebird, SQLite and ODBC. Free Pascal has no SQL Server connector for macOS: use ODBC with the FreeTDS ODBC driver.
  • Zeos connections, with the same databases.
  • The Reportman DB Agent driver (through the Hub) needs OpenSSL 3, see the requirements.

The client library of each database is looked for in this order:

  1. The one of the connection: VendorLib (FireDAC connections) or LibraryLocation (Zeos), with the full path of the .dylib.
  2. The library search of macOS (~/lib, /usr/local/lib).
  3. The folders of the usual installers:
DatabaseClient library found in
PostgreSQLHomebrew (libpq, postgresql@N), Postgres.app, the EnterpriseDB installer (/Library/PostgreSQL/N), MacPorts
MySQLthe MySQL package (/usr/local/mysql), Homebrew (mysql-client, mysql), MacPorts
MariaDBHomebrew (mariadb-connector-c)
Firebirdthe Firebird package (/Library/Frameworks/Firebird.framework)
ODBCunixODBC of Homebrew or MacPorts, and the iODBC of macOS
SQLitethe one of macOS

Do not put the lib folder of a database server in DYLD_LIBRARY_PATH: those folders carry their own libiconv, libssl and others, which hide the ones of macOS and break other libraries.

Differences and limitations

  • The SQL editor of the designer is the native editor with schema completion and the AI inline suggestion, as on Linux (the Monaco editor is Windows only).
  • Not tested yet: Apple Silicon (arm64; the Free Pascal disk image includes its compiler) and printing.
  • No signed and notarized application bundle to distribute yet.

The technical notes of the port are in docs/macos.md of the source code.
