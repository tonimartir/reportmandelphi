Report Manager en JavaScript: los paquetes de npm

This page in English

Los paquetes @reportman/* de npm son el motor de Report Manager escrito en JavaScript: abren un informe .rep, lo componen y escriben su PDF sin binarios nativos, sin WebAssembly, sin Docker y sin dependencias del sistema operativo. Funcionan en Node.js y en el navegador, y son una traducción del motor .NET de la misma versión: los dos están hechos para dar la misma salida con el mismo informe.

Versión preliminar. Ésta es la preliminar de la 4.1.0, publicada con la etiqueta de npm next (npm install @reportman/node@next). La API todavía puede cambiar antes de la 4.1.0 definitiva, así que fije la versión exacta que instale si va a construir sobre ella ahora.

Requisitos

Node 22.12 o posterior. Los paquetes son módulos ES y no hay compilación CommonJS; un programa CommonJS los carga con require(), que Node admite para módulos ES. En el navegador no necesitan ningún añadido al empaquetador: son JavaScript corriente.

Los dos pasos: describir los parámetros y ejecutar

Un informe se ejecuta en dos pasos, como en los demás motores. Primero se le pregunta qué parámetros tiene, para que su programa (o su usuario) los rellene; después se ejecuta con esos valores. El anfitrión le da al motor los bytes del informe, el acceso a los datos y las fuentes —el motor no hace entrada ni salida por su cuenta—.

import { writeFileSync } from 'node:fs';
import { openReport, sqlite } from '@reportman/node';

const report = await openReport('invoices.rep', {
  connections: { SAMPLES: sqlite('samples.db') },
  fonts: {}, // las fuentes TrueType del sistema; sin esto, las 14 estándar del PDF
});

// Paso 1: qué pide el informe
console.log(await report.describeParameters());

// Paso 2: ejecutarlo con esos valores
writeFileSync('invoices.pdf', await report.executeToPdf({ FIRST_ORDER: 7, LAST_ORDER: 9 }));

En la línea de comandos, y sin escribir código

@reportman/node instala reportman-pdf, que hace los mismos dos pasos desde una consola:

npm install @reportman/node@next
npx reportman-pdf invoices.rep --describe --sqlite SAMPLES=samples.db
npx reportman-pdf invoices.rep -o invoices.pdf --sqlite SAMPLES=samples.db -paramFIRST_ORDER=7 -paramLAST_ORDER=9

Y para ver los informes de ejemplo funcionando sin instalar nada ni escribir una línea de código, @reportman/server los sirve con su propia consola y su explorador de la API:

npx @reportman/server --samples

Escribe los ejemplos y su base de datos en ./reportman-data, imprime la clave de la consola y escucha en http://127.0.0.1:8080/. El explorador ejecuta cada ejemplo a PDF, metafichero, texto o CSV, y muestra la misma llamada para curl, PowerShell, JavaScript, C# y Delphi.

Ese servidor habla la misma API que Reportman Server y lee la misma carpeta de datos, pero no diseña informes: véase los cuatro servidores de Report Manager, uno al lado del otro.

El diseñador web, dentro de su propia aplicación

El diseñador de informes funciona también en el navegador, y una aplicación de Node.js puede servirlo ella misma. El diseñador es un elemento propio, <reportman-designer> (@reportman/designer), y su parte de servidor es @reportman/designer-server, montada en una ruta de su propia aplicación —con node:http, Express o Fastify—. Se sirve desde su mismo origen, así que comparte su sesión, y no necesita contenedor ni .NET:

import express from 'express';
import { createDesignerServer, nodeHandler } from '@reportman/designer-server';

const designer = createDesignerServer({
  dataPath: './reportman-data',          // los informes y las conexiones
  authorize: (check, request) => request.raw.user?.canDesignReports === true,
});

const app = express();
app.use(nodeHandler(designer));          // /api/designer/* y el diseñador en /designer/
app.listen(3000);

Abre los informes de una carpeta de datos con la misma disposición que la de Reportman Server, los guarda en el mismo .rep XML llano que leen los diseñadores de Delphi y .NET, previsualiza su PDF con el motor de JavaScript y lee el esquema de sus conexiones para el editor de SQL. Quién puede diseñar es cosa de su aplicación: sin authorize, el diseñador contesta solo a la máquina en la que corre, y la comprobación que recibe dice qué se está pidiendo —abrir o ejecutar los informes de un alias, guardar en él, o abrir datos y evaluar expresiones—.

El copiloto de IA no forma parte de esto: el asistente vive en Reportman Server, y aquí el diseñador se abre sin él (no-ai).

@reportman/designer y @reportman/designer-server llegan a npm con la siguiente publicación de la versión preliminar. Su código fuente ya está en el repositorio, y la demo del diseñador en vivo los ejecuta en su propio navegador: allí el diseñador entero —su parte de servidor también— funciona dentro de la página, sin servidor ninguno, y esa página pasa su copiloto al servicio de IA de Report Manager.

Bases de datos

El motor lee los datos a través de un paquete de acceso, uno por sistema, con el mismo comportamiento que los proveedores de .NET. Instale el que necesite junto a @reportman/node:

Base de datosPaquete
PostgreSQL@reportman/driver-postgres
MySQL y MariaDB@reportman/driver-mysql
Microsoft SQL Server@reportman/driver-mssql
Firebird@reportman/driver-firebird
Reportman DB Agent, por el Hub@reportman/driver-http

SQLite no necesita ningún paquete de acceso: @reportman/node lo lee con el node:sqlite de Node. El del Agent es el único que funciona también en el navegador, porque habla HTTP con el Reportman DB Agent a través del Hub en lugar de abrir él mismo una conexión a la base de datos.

Informes guardados en XML, e informes guardados en DFM

Como en el motor .NET, los lectores aceptan ficheros .rep en XML, comprimidos o no, y ésos no necesitan nada más. Un informe que Delphi guardó en un formulario DFM necesita el paquete opcional @reportman/dfm, que lo convierte al XML que Delphi escribe para él; @reportman/node lo usa por su cuenta cuando está instalado. La otra salida es volver a guardar el informe en XML, desde el diseñador o con reptotxt -xml.

Pruébelo, y la referencia

  • La demostración en vivo — los informes de ejemplo ejecutados en su propio navegador, con estos mismos paquetes: el formulario de los parámetros, la vista previa de las páginas y el PDF.
  • La demo del diseñador en vivo — el diseñador web en su navegador: abra un informe de ejemplo, cambie sus elementos, sus expresiones y su SQL, previsualice su PDF y guárdelo.
  • La galería de ejemplos — los once informes de ejemplo con una imagen de su primera página, sus ficheros .rep, los PDF que el motor hace de ellos y cómo ejecutar cada uno.
  • @reportman/node en npm — y desde ahí todos los demás paquetes del conjunto.
  • El motor en TypeScript — qué hace cada paquete, con qué reglas está construido y cómo se comprueba contra los motores .NET y Delphi. Cada paquete tiene su propio README con su API.

Los ficheros de informe son los mismos que abren los diseñadores de Delphi y .NET, así que un informe diseñado con cualquiera de ellos funciona aquí sin tocarlo. Véase también la biblioteca .NET y las herramientas de la línea de comandos.
