PDF output implementation

Developer

Adobe PDF output

Native PDF output is implemented: the translation goes straight from the Report Manager metafile to the PDF format, which is why it is far faster than printing through Acrobat Distiller or any other PDF print driver.

To embed the TrueType fonts of a report, in the designer select Edit › Select all texts and then, in the object inspector, set the PDF Font property to Truetype font. The property also offers the standard Type 1 faces (Courier, Times, Helvetica, Symbol, ZapfDingbats) and Linked, which names the font in the PDF without carrying it. A PDF/A-3 report ignores the choice: there, every font is embedded.

How a font gets into the PDF

The path is the same on the three platforms — only the libraries underneath change:

  1. Selection. The font name of the report becomes a font of the system, with a sensible substitute when it is not installed: GDI on Windows, Fontconfig on Linux, Core Text on macOS.
  2. Measuring and shaping. The text is laid out with DirectWrite on Windows, HarfBuzz with FreeType and ICU on Linux, and Core Text on macOS, so Arabic, Hebrew, the Indic scripts, bidirectional paragraphs and HTML runs are shaped before they reach the PDF. The driver writes the glyphs and their positions, one by one, and not a string of characters.
  3. Subsetting. Only the glyphs the report uses are embedded. On Linux and macOS the cut is made with hb-subset, which also handles CFF outlines, font collections and variable fonts; on Windows a built-in TrueType subsetter does it. A face that cannot be cut safely — a CFF face inside a .ttc collection without hb-subset — is not chosen as a substitute: a gap is better than a PDF carrying something that is not a font.
  4. Writing. The font goes in as a composite (Type 0) font with Identity-H encoding and a CIDFontType2 descendant (/FontFile2); an OpenType font with CFF outlines goes as CIDFontType0 (/FontFile3 /OpenType) instead, which is what its glyph data really is. Each glyph carries its own width, and a ToUnicode CMap maps the glyphs back to text, so the PDF can still be searched and copied — including the glyphs the shaper substituted. A Type 1 font goes in whole, as a /FontFile program and without subsetting, because its outlines are not cut by either subsetter.

Windows

Microsoft Windows already has a font cache: any application can query information about the installed fonts, obtain the whole font file (to embed it), and ask the operating system for the closest match when the requested font is not available (font matching). This works for TrueType and OpenType fonts, although a few fonts cannot be embedded because the API does not allow retrieving their font data, perhaps because of distribution-license restrictions.

Text is measured and shaped with DirectWrite when it is present; on an old Windows without it, the engine falls back to plain GDI measurement, which does not shape complex scripts.

Linux

Linux does not provide a single standard font service in the operating system; instead, fonts are handled through libraries such as Fontconfig and FreeType.

Font selection uses Fontconfig, which provides a sensible fallback when the requested font is not available. The older mechanism — scanning the font directories listed in /etc/fonts/fonts.conf and matching fonts with a simple built-in algorithm — is used only when Fontconfig is not present on the system. Installing Fontconfig is recommended for correct font selection. It is available on virtually every Linux distribution (package fontconfig, shared object libfontconfig.so) and is already present on most desktop systems; minimal or console installations may need to add it.

For the font data itself — reading glyphs and embedding the font file in the PDF — Report Manager uses the FreeType library (package freetype2, shared object libfreetype.so), which is also installed by default on most distributions and is needed only when you embed or link TrueType, OpenType or Type1 fonts. Because FreeType exposes Type1 font information, Type1 fonts can be linked or embedded whole, while TrueType and OpenType fonts are embedded as the subset the report uses. HarfBuzz (libharfbuzz.so) shapes the text and cuts the subset that is embedded.

Font information is cached the first time a TrueType font is embedded; building that cache means reading the installed font files to obtain their names and styles, so the first run of a single report (for example with the printreptopdf command line tool) carries a one-off cost. It does not appear if you do not embed PDF fonts, and is usually unnoticeable depending on how many fonts are installed.

The good thing is that you do not need a running X server to generate PDFs with TrueType embedding.

macOS

On macOS the text is selected, measured, shaped and painted with Core Text, the text engine of the system, so the preview, the printed page and the PDF show the same glyphs. Setting the environment variable RP_TEXT_ENGINE=freetype goes back to the Linux path (HarfBuzz, FreeType and Fontconfig), which is useful to compare one against the other.

Embedding is the same as on Linux: the subset is cut with HarfBuzz over the font file and the index of the face inside it, so HarfBuzz is loaded even when Core Text is doing the typography. The designer distributed for macOS carries its own FreeType, HarfBuzz and Fontconfig, so nothing has to be installed.

PDF/A-3

Besides the ordinary PDF 1.4 output, the engine writes PDF/A-3, conformance level B: a PDF meant to be archived, and the format that lets you carry the machine-readable original of a document — the XML of an electronic invoice, for example — inside the PDF a person reads.

It is chosen per report, in the designer, in Page setup › Conformance, and it is saved in the .rep file, so printreptopdf, the report servers and the components honour it without being told again.

What the engine writes for it:

  • A PDF 1.7 file with the sRGB output intent and its ICC profile embedded, so the colours are defined without depending on the device.
  • XMP metadata declaring pdfaid:part 3 and pdfaid:conformance B, with the title, author, subject, keywords and creation date of the document.
  • Every font embedded: neither font linking nor the standard Type 1 faces are allowed, and a font whose data cannot be read stops the export with an error instead of producing a file that is not PDF/A.
  • The attached files, each with its MIME type and its AFRelationship — Data for the XML a machine reads, Source for the file the document was made from, Alternative, Supplement or unspecified — listed both in the embedded-files name tree and in the /AF array of the document.

Attachments are added in the designer, with the file name, the MIME type, the relationship, a description and the ISO dates, or from code with AddEmbeddedFile (also available to the ActiveX and the .NET library). AddMetadata sets the document information, and AddXMPMetadata appends your own XMP: it is written after the metadata the engine generates, so pass a complete <rdf:Description> with the namespaces it uses — and, if they are not the standard ones, the PDF/A extension schema that describes them.

Level B covers the visual appearance of the document. Level A, which also requires the document to be tagged for accessibility, is not produced.

Issues and limitations

  • Unicode is supported as far as the font goes: a character the font has no glyph for is drawn with the face the system substitutes, and that face is embedded too.
  • JPEG images travel into the PDF as they are (DCTDecode); any other image is written as a bitmap compressed with FlateDecode.
  • Compression is used by default and can be turned off in Page setup. Some very old PDF viewers do not read compressed files; the official Adobe reader has no such problem.
  • The standard Type 1 faces (Courier, Times, Helvetica) give the smallest and fastest file, because nothing has to be carried — but they are not an option in PDF/A.
  • Embedding grows the file even with the subset, and the growth is per font and style. Font linking is the alternative when you know the destination computers have the font installed.
  • A font licence can forbid embedding — the fsType field of the font says so — so check the licence of the fonts you embed. Windows may also refuse to hand over the font data of some fonts, and then the font cannot be embedded at all.
