.NET C# engine port and usage

Report Manager for Dot Net

Basics

The dot net version of Report Manager is a full translation from Delphi to C# of the reporting engine. The port is complete, but some features are still not implemented. Libraries are provided so you can link easily your reports with your application. The .Net native port of the Report Designer is still in progress so, the design and test of the reports are done by the classic designer (32bit or 64bit)

How to design reports for .Net

Design the report normally but:

  • Set at page setup, options tab the preferred save method to XML or XML compressed. The .net runtime read and save the reports in this new formats.
  • A report converted from Delphi (one whose connections use a driver of the Delphi engine, such as FireDAC, Zeos, IBX or dbExpress, converted by ConvertToDotNet) formats dates and numbers with the Delphi masks. Any other report uses the .Net format strings: M is the month, m the minutes and H the 24 hour format hour. See Differences from the Delphi engine.
  • For linked queries, the parameters of the child dataset must be defined in Parameters definition and must be assigned to the child dataset.

Missing parts

  • Native .net Report Designer is not implemented (Win32/Win64 designer can be used)

Different behaviour

  • In odbc provider you use the ? symbol for placing parameters, the parameters will be assigned by position, not by name, parameters by name are not supported by odbc dot net driver, so make sure to sort the parameters to match query position when you use odbc.
  • Format property for expressions use the .net format strings, except in a report converted from Delphi.

Differences from the Delphi engine

The .Net engine and the TypeScript engine (the @reportman npm packages, a translation of the .Net one) give the same output for the same report, and are checked against the Delphi engine. Where .Net already had a behaviour of its own, a report converted from Delphi gets the Delphi one and any other report keeps the .Net one. These are the differences that remain (version 4.1):

Text and layout

  • The line spacing of the standard PDF fonts is the same in the three engines: a text of n lines measures n line spacings (1.143 times the font size for Helvetica, 1.131 for Times, 1.139 for Courier). Before version 4.1 the .Net engine added a leading (0.135 times the size) to the height of every text.
  • The FreeType text device of .Net measures the standard PDF fonts with TrueType metrics: up to one twip per line of difference.
  • With FireDAC, the Delphi engine receives text fields without their trailing spaces and line breaks (FireDAC trims them by default, FormatOptions.StrsTrim). The .Net and TypeScript drivers return the text as it is stored, so a memo that ends in blank lines makes its section that much taller.

Expressions and formats

  • A report converted from Delphi follows the Delphi engine in display formats (FormatFloat, FormatDateTime and Format masks, numbers and dates without a mask), comparisons with NULL (NULL is less than any value, and '' equals NULL), REPLACESTR (not case sensitive), SUBSTR, MONTHNAME, VAL and ISNUMERIC, the sample standard deviation, and the parameter order (Top, Left) of GRAPHICOP, TEXTOP, IMAGEOP and BARCODEOP.
  • By design the .Net engine uses decimal numbers where Delphi uses Double or Currency (a rounding of a half may differ), compares texts by culture, applies AND and OR to numbers, carries NULL through arithmetic and sets the culture from the language of the report.
  • The .Net expression parser stops at a character it does not know (1 != 2 evaluates as 1) where Delphi gives a syntax error.
  • MONTH and YEAR of a number return a value in .Net; Delphi gives an error.
  • Masks with * (FORMATNUM) are not supported by .Net.
  • In the Delphi engine FORMATSTR ignores the mask of a 64 bit integer, MOD works with 32 bit integers and a literal such as 1E-10 is a syntax error.

Barcodes

  • The error correction level of a QR code is numbered differently: 2 L, 3 M, 4 Q and 5 H in .Net (any other value is L), 0 L, 1 M, 2 Q and 3 H in Delphi.
  • Data a symbology cannot encode (letters in an EAN-8, for example) stops the .Net report with an error that names the symbology and the data (EAN8 bad Data: 1234567X); Delphi draws bars that no reader reads.
  • A rotated barcode reads back at 90, 180 and 270 degrees in every engine; at other angles no engine draws a readable symbol.
  • Code 39 with checksum has no stop character in any engine.
  • A receipt printer that draws barcodes by itself does not get PDF417 symbols from the TypeScript engine yet.

Charts

  • Delphi draws charts with TeeChart and .Net with its own drawing: the same data, a different look. A color or a series change expression of another type stops the .Net report with a type conversion error.

Using the library

To use the libraries provided, you should include a reference to them in your project. It' better if you include the .csproj to your project and then a reference to that project so you can debug any problem deeper.

Documentation is available

This is sample code to execute a report, a portion of the sample provided testinglib.exe.

using Reportman.Drawing;

using Reportman.Drawing.Forms;

using Reportman.Reporting;

using Reportman.Reporting.Forms;

Report rp=new Reportman.Report();
rp.LoadFromFile(EFile.Text);
rp.ConvertToDotNet();

// Set the provider factory for each database, user the invariant name of the factory (defined in machine.config)

rp.DatabaseInfo[0].ProviderFactory = "YourDatabasefactory";

// As an alternative you can provide an already established connection and transaction

// rp.DatabaseInfo[0].Connection =YourIDBConnection

// rp.DatabaseInfo[0].Transaction=YourIDBTransaction


if (pdf)
{
rp.AsyncExecution=false;
PrintOutPDF printpdf = new PrintOutPDF();
printpdf.FileName=pdffilename;
printpdf.Compressed=compressedpdf;
printpdf.Print(rp.MetaFile);
}
else
{
rp.AsyncExecution=asyncexecution;
if (ParamsForm.ShowParams(rp)
{
PrintOutWinForms prw = new PrintOutWinForms();
prw.Preview = preview;
prw.SystemPreview=systempreview;
prw.ShowPrintDialog=showprintdialog;
prw.Print(rp.MetaFile);
}
}
